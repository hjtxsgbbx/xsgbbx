## 1. 引言与项目背景

### 1.1 项目目标
agent_1 是一款**跨平台 AI 编程助手**，通过自然语言交互帮助开发者在本地项目中完成代码读写、命令执行、文件管理、Git 操作等任务。系统以 **TAOR (Think-Act-Observe-Reflect) 循环** 为核心，提供安全、可干预、可恢复的命令执行环境。

**当前阶段策略**：优先完成并交付**终端 CLI 版本**（MVP），桌面端与 Web 端作为战略级高优先级方向，但仅在 CLI MVP 稳定交付且资源允许时启动，当前交付范围**严格限定为 CLI MVP**。

### 1.2 用户画像
| 画像 | 描述 | 核心诉求 |
|---|---|---|
| 全栈开发者 | 频繁在终端中编码、调试、提交 | 快速实现需求，减少上下文切换 |
| DevOps/SRE | 需要执行运维脚本、日志分析 | 安全执行命令，防止误操作 |
| Windows 开发者 | 在 PowerShell / CMD / Git Bash 环境下工作 | 原生体验，无需切换操作系统 |
| Linux 开发者 | 在 GNOME Terminal、Konsole 等多种终端中操作 | 跨终端一致的界面与行为 |
| 技术领导者 | 审视方案、生成 PR 描述 | 理解变更，控制风险 |

### 1.3 核心使用场景
1. **代码修改闭环**：开发者描述需求 → agent_1 修改代码 → 运行测试 → 自动 commit。
2. **问题排查**：agent_1 分析错误日志、执行诊断命令并给出修复建议。
3. **项目引导**：新成员通过 agent_1 快速理解项目结构和约定。
4. **持续小幅迭代**：开发者在中途随时介入修改 agent_1 的方向，无需停止会话。

## 4. 架构设计

系统整体采用 **多端统一核心 + 平台抽象层 + UI 适配** 的架构。当前 MVP 聚焦 CLI 实现，桌面和 Web 端架构预留扩展点。

```mermaid
flowchart TD
    subgraph 入口
        CLI[CLI: React + Ink]
    end

    subgraph 核心层
        Engine[QueryEngine: TAOR 循环]
        Perm[四层权限流水线]
        Tools[工具执行器 / PAL]
        Compact[上下文压缩]
        Heal[错误自愈]
    end

    subgraph 数据与适配
        PAL[Platform Abstraction Layer]
        Storage[本地存储 / 会话同步]
    end

    CLI --> Engine
    Engine --> Perm --> Tools
    Engine --> Compact --> Heal
    Tools --> PAL
    Storage --- Engine
```

### 4.0 平台抽象层 (PAL)

| 抽象接口 | Windows 实现 | Unix 实现 (macOS/Linux) |
|---|---|---|
| `shell.exec(command)` | PowerShell / CMD (根据环境自动选择) | Bash / POSIX sh |
| `fs.setPermissions(path, mode)` | `icacls` 等效设置 | `chmod` |
| `keychain.get/set/delete` | Windows Credential Manager | macOS Keychain / `secret-tool` (Linux) |
| `sys.tempDir()` | `%TEMP%` | `/tmp` |
| `sys.homeDir()` | `%USERPROFILE%` | `$HOME` |
| `sys.isElevated()` | 检测 Administrator 权限 | 检测 `root` / `sudo` |

命令执行前统一由 `CommandAdapter` 转换，并经过 AST 安全扫描。Windows cmd.exe 支持完整的路径处理、环境变量展开（`%VAR%`）和安全转义。

### 4.1 启动流程与知情同意
首次使用 CLI 时，强制展示《数据透明声明》：
```
================================================
  agent_1 需要将您的部分代码发送至 AI 提供商
  以获得智能回复。详情请阅读隐私政策。
================================================
  提供商选择: [1] Anthropic  [2] OpenAI
  输入数字选择并确认 (或 'q' 退出): _
```
用户必须显式同意并选择 AI 提供商方可继续。之后每次会话开始时，UI 会持续显示数据接收方指示器。

CLI 启动参数：
- `--version/--help`：打印信息并退出
- `-p`：无头模式，用于自动化脚本（需附带 `--accept-terms` 参数）
- 默认无参数：进入交互 REPL

### 4.2 交互初始化（main.tsx 三段式启动）
1. **平台检测与适配**：识别操作系统和终端类型，加载对应 PAL 实现和 UI 组件。
2. **进程状态初始化** (T2)：加载配置、恢复上次会话（如果存在且未过期）。
3. **渲染 App** (T3)：启动 React+Ink 渲染引擎，绘制终端 UI。
4. **并行加载**：读取 `.agent_1.md` 项目记忆（前 200 行索引），建立 MCP 懒连接。
5. **REPL 就绪**：通过 Channels 封装标准输入，进入待命状态。

### 4.3 上下文组装
每次用户输入文本，`handleSubmit` 将其传递给 `QueryEngine.query`。系统**并行组装**以下内容：
- 系统提示词（含平台信息、权限模式、当前项目结构摘要）
- 可用工具列表及签名
- 预压缩检查（计算当前 Token 用量，提前规划压缩策略）

随后 `prependUserContext` 将 `.agent_1.md` 前 200 行索引注入上下文。根据配置决定加载全部工具（Default 模式）或仅只读白名单（Plan 模式）。

### 4.4 TAOR 主循环 (queryLoop)
循环在 `MAX_TURNS` 次迭代内执行，默认 50 次，可配置。

**循环体**：
1. **判断循环条件**：若 `loop >= MAX_TURNS`，强制退出并提示用户 `⚠ Maximum turns (50) reached. Task incomplete. Continue? (c/s)`。
2. **① THINK：调用 AI API** (`callModelAPI`)。请求体包含所有历史消息（或压缩后的摘要）、系统提示词和工具定义。API 返回响应后：
   - **纯文本**：添加 `assistant` 消息到上下文。
   - **含 tool_calls**：提取工具调用列表，进入流式工具执行阶段。
3. **流式工具执行**：`StreamingToolExecutor` 在模型尚未完全输出完毕时即开始执行工具调用，减少等待时间。
4. **判断 stop_reason**：若为 `end_turn` 且无工具调用，任务完成，跳转至交付阶段。否则继续循环。

### 4.5 权限检查（四层流水线）
工具执行前，所有调用依次通过四层检查：
1. **规则缓存**：查找历史相同操作的允许/拒绝记录，若命中且未过期则直接返回决策。
2. **acceptEdits 模拟**：根据用户过往行为预判是否放行。
3. **只读白名单**：若操作为只读且在白名单内，直接允许。
4. **AI 分类器**：调用轻量模型或规则引擎进行语义判断。

任何一层返回 `DENIED`，则终止执行并展示理由。用户**只能覆盖 AI 分类器层的拒绝**，其他三层不可覆盖。覆盖时需输入确认短语 `I understand the risk`。

### 4.6 工具执行
根据工具类型分发：
- **CommandTool**：通过平台适配器调用原生 Shell。命令先经 AST 解析，若子命令数量 > 50，强制询问用户确认后才执行；否则经过 denyList 检查。
- **AgentTool**：启动子智能体，在独立上下文中通过邮箱模式通信，仅返回摘要。
- **其他工具**（Edit/Grep/Glob 等）：直接执行，使用 Node.js 跨平台 API。

### 4.7 错误自愈
工具执行返回 `ToolResult` 后，若失败，系统根据错误代码映射到五种策略之一（概率可配置）：
- **RETRY (55%)**：调整参数后立即重试，最多 3 次。
- **INVESTIGATE (28%)**：执行诊断命令收集环境信息。
- **FIX (14%)**：尝试修改命令或代码（如纠正拼写、添加缺失的包）。
- **PIVOT (2%)**：放弃当前路径，改用其他方案。
- **ASK (1%)**：暂停并向用户求助。

重试上限 3 次防止死循环。

### 4.8 上下文压缩（四级策略）
每次 `OBSERVE` 阶段结束后调用 `checkAndCompact`：
1. **截断**：单条输出超过 8000 字符的部分截断，保留头尾。
2. **按条件触发压缩**：
   - Token 用量 > 60% → **SnipCompact**：裁剪最早的非关键消息。
   - 空闲 > 5 分钟 → **MicroCompact**：轻量折叠，不调用模型。
   - Token 用量 > 70% → **ContextCollapse**：调用模型对历史对话进行摘要。
   - Token 用量 > 92% → **AutoCompact**：激进摘要，丢弃最旧的非必要对话轮次。

被标记为 `critical: true` 的消息（如错误信息、用户明确要求记住的内容）**永不丢弃**。系统通过关键词检测和用户 `/mark` 命令自动/手动设置 `critical` 标记。

### 4.9 用户中途干预（h2A 双缓冲队列）
用户在 AI 执行过程中输入新指令时，`h2A` 队列监听。若当前操作允许注入，则更新约束、重定向任务目标；否则指令排队，待当前工具执行完毕后立即处理。干预输入以 `>>` 前缀显示。

### 4.10 交付与后台
任务完成后：
1. **测试修复闭环**：若有测试命令，循环运行并自动修复（最多 3 次重试）。
2. **生成 Commit Message**：基于对话和变更生成约定式提交，执行 `git add -A && git commit`（可通过 `--confirm` 手动确认，也可关闭自动提交）。
3. **自动 PR**：若 `autoCreatePR` 开启，则 `git push` 并创建 PR；否则导出会话总结（Markdown + 成本统计）。
4. **会话结束**。

## 5. 数据设计

所有持久化数据存储在 `~/.agent_1/` 下，权限为 `0600`（Unix）或等效 ACL（Windows）。

### 5.1 核心数据 Schema

#### 5.1.1 会话历史 (`sessions/{session_id}.json`)
```typescript
interface Session {
  session_id: string;
  created_at: string;
  updated_at: string;
  client_type: "cli" | "desktop" | "web";
  status: "active" | "completed" | "terminated";
  messages: Message[];
  meta: {
    project_path: string;
    model: string;
    provider: string;
    cost_estimate: number;
    platform: string;
    terminal: string;
  };
}

interface Message {
  role: "user" | "assistant" | "tool";
  content: string | ToolCall[];
  timestamp: string;
  critical: boolean;
  tool_id?: string;
}

interface ToolCall {
  id: string;
  name: string;
  arguments: Record<string, unknown>;
}
```

#### 5.1.2 用户配置 (`config.json`)
```typescript
interface Config {
  version: number;                 // 当前为 3
  permission_mode: "default" | "plan";
  auto_create_pr: boolean;         // 默认 false
  auto_commit: boolean;            // 默认 true
  accept_terms: boolean;
  chosen_provider: string;
  session_retention_days: number;  // 默认 30，自动清理在 M2 后期实现
  telemetry_enabled: boolean;
  max_turns: number;               // 默认 50
  model: string;
  fallback_model?: string;
  api_key_ref: string;
  ui: {
    color_theme: "dark" | "light";
    compact_mode: boolean;
  };
  compaction_thresholds?: {
    snip: number;
    collapse: number;
    auto: number;
  };
  ai_safety_confidence_threshold?: number; // 默认 0.7
}
```

#### 5.1.3 遥测日志 (`logs/agent_1.log`)
每行 JSON：`{ timestamp, level, message, session_id }`。消息内容不包含命令文本、文件路径或项目名，仅含操作类型和安全事件摘要。滚动保留 30 天，总大小 100 MB。

#### 5.1.4 审计日志 (`audit/{audit_session_id}.log`)
```typescript
interface AuditLogEntry {
  timestamp: string;
  session_id: string;
  action: "tool_exec" | "permission_denied" | "permission_overridden" | "config_change";
  tool_name?: string;
  command_summary?: string; // 命令类型，不含具体参数
  decision: "allowed" | "denied" | "overridden";
}
```
审计日志存储在 `~/.agent_1/audit/` 目录，不包含敏感数据，用于安全追溯。用户执行 `agent_1 purge --all` 可一并删除所有本地数据（会话、遥测、审计日志），但已发送至 AI 提供商的代码片段需用户自行向提供商申请删除。

### 5.2 数据库迁移
- 配置文件版本号递增，新增字段提供默认值。
- 会话历史、审计日志格式变更提供转换脚本。

## 6. 安全与隐私合规

### 6.1 持续数据透明指示器
CLI 空闲态底部状态栏常驻 `📡 已发送至 [提供商] | 上次: Xs 前`。`/status` 命令查看详情。桌面/Web 端设计预留同类指示器。

### 6.2 统一数据发送表述
全文统一表述：“agent_1 不会在您不知情时自动上传代码。每次您请求 AI 回复时，会主动将相关代码片段和项目上下文发送至您选择的 AI 提供商。”

### 6.3 风险缓解与 AI 输出安全控制
- **AI 输出验证**：命令存在性检查（Unix: `which`，Windows: `Get-Command`）、参数合理性校验、置信度评估（阈值初始 0.7，可调）。M2 前期交付《AI 输出安全详细设计》，包含基线数据集构建方案、校准流程和验收标准。
- **权限覆盖策略**：仅可覆盖 AI 分类器层，需输入 `I understand the risk`。
- **Windows 高危命令**：动态黑名单（`format`, `diskpart` 等），每季度审核，用户可通过 `/config deny add` 自定义。
- **挫折感检测**：仅针对模型输出，可关闭。

### 6.4 第三方 SDK 披露与隐私影响
agent_1 依赖以下第三方 SDK：

| SDK | 版本 | 用途 | 采集数据类型 | 数据传输目的地 |
|---|---|---|---|---|
| `@anthropic-ai/sdk` | latest | 调用 Anthropic Messages API | 对话内容、项目上下文、文件片段（均由用户主动发送） | Anthropic 服务器（默认美国，可配置欧盟） |
| `openai` | latest | 调用 OpenAI Chat Completions API | 同上 | OpenAI 服务器（默认美国，可配置） |

上述 SDK 仅发送用户主动传入的数据，不会静默采集设备信息、个人身份信息或使用统计数据。用户选择提供商后对应 SDK 才会被加载。agent_1 已与两家提供商签署 DPA。

### 6.5 隐私合规与用户权利
- **数据跨境传输**：默认使用欧盟区域 API endpoint，已签署 DPA（数据处理协议）。
- **隐私政策**：已通过法务终审，全文见仓库 `PRIVACY.md` 及官网。摘要见附录 B。
- **遥测匿名化**：遥测不记录命令文本、文件路径、项目名、IP 地址。
- **用户权利操作路径**：
  - 数据导出：`agent_1 export --format json`
  - 数据删除：`agent_1 purge --all`（删除所有本地会话、审计日志和遥测）
  - 已发送至 AI 提供商的数据需自行向提供商申请删除，agent_1 无法撤回。

### 6.6 端到端通信安全

## 8. 接口设计（API 契约）

### 8.1 核心模块接口（TypeScript）
```typescript
interface QueryEngine {
  query(input: UserInput, context: SessionContext): Promise<QueryResult>;
}

interface UserInput {
  text: string;
  timestamp: string;
  interrupt?: boolean; // h2A 干预
}

interface SessionContext {
  messages: Message[];
  config: Config;
  platform: PlatformInfo;
  projectMemory: string; // .agent_1.md 前200行
}

interface QueryResult {
  response: AssistantResponse;
  toolCalls?: ToolCall[];
  stopReason: "end_turn" | "max_tokens" | "tool_use" | "stop_sequence";
}

// Tool 接口
interface Tool {
  name: string;
  description: string;
  parameters: JSONSchema;
  execute(params: Record<string, unknown>, context: ExecutionContext): Promise<ToolResult>;
}

interface ExecutionContext {
  session: Session;
  platform: PlatformInfo;
  permissionLevel: PermissionDecision;
}

interface ToolResult {
  success: boolean;
  output: string;
  errorCode?: string;
  artifacts?: string[];
}

// 权限决策
interface PermissionDecision {
  allowed: boolean;
  reason?: string;
  layer: "cache" | "acceptEdits" | "whitelist" | "ai_classifier";
}

// 桌面/Web 桥接接口预留
interface AgentBridge {
  invokeQuery(input: UserInput): Promise<QueryResult>;
  onStreamData(callback: (chunk: string) => void): void;
  abortQuery(): void;
}

type WSMessage =
  | { type: "query"; payload: UserInput }
  | { type: "result"; payload: QueryResult }
  | { type: "error"; code: number; message: string };
```

### 8.2 外部 API 接口
- 遵循所选 AI 提供商的 Chat Completions API 规范（Anthropic Messages API、OpenAI Chat Completions）。
- 使用标准 HTTP POST，JSON 请求/响应。
- 错误处理：HTTP 4xx/5xx 重试或降级。

### D. 关键架构决策记录 (ADR)

1. **选择 TAOR 循环而非标准 ReAct**：需要流式工具执行和灵活的错误恢复。
2. **采用多端统一核心策略**：CLI、桌面、Web 共享 TAOR 引擎和权限模型，降低维护成本。
3. **桌面端选择 Electron**（后续版本）：需要 Monaco Editor 和 React 生态。
4. **Web 端采用 WebSocket 远程连接**（后续版本）：保持代码在本地执行的安全承诺。
5. **引入平台抽象层 (PAL)**：解耦核心逻辑与 OS 差异，支撑跨平台。
6. **四层权限流水线**：逐层过滤，并明确各层不可覆盖性。
7. **上下文压缩采用四级策略**：平衡信息保留与 Token 消耗。
